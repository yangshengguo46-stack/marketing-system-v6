# Agent 第一性原理

## 1. 定义

Agent 不是“会聊天的模型”，也不是“把步骤画成流程图的应用”。

> Agent 是一个能够代表用户，持续观察当前状态，由模型判断下一步，调用工具改变或读取环境，检查结果，并在权限边界内推进到目标或真实阻塞的系统。

最小闭环是：

```text
目标与角色
-> 观察用户、状态和环境
-> 模型形成判断
-> 回答或选择行动
-> 工具执行并返回真实结果
-> 更新状态并验证
-> 完成、继续、纠正或交回用户
```

如果代码预先决定了每一步，模型只负责填字段，那是 workflow。Workflow 可以是 Agent 使用的执行能力，但不应
冒充 Agent 的思考。反过来，如果只有模型自由输出，却没有真实工具、状态、权限和验证，它仍只是聊天模型。

## 2. 八个不可互相替代的组成

| 组成 | 回答的问题 | 不应承担 |
|---|---|---|
| 身份与使命 | 我是谁、替谁工作、长期要达成什么 | 行业知识、固定工作流、项目事实 |
| 模型判断 | 当前应该注意什么、如何解释、下一步做什么 | 密钥保管、幂等、数据库一致性 |
| Agent Loop | 是否继续、调用什么、如何根据结果修正 | 替模型写死营销结论 |
| 状态与事实 | 用户、项目、账号、证据和结果当前是什么 | 用聊天记忆猜测真实业务状态 |
| Skill/知识 | 某类任务有哪些可复用方法和参考 | 永久改写身份、强制每轮执行 |
| Tool/执行 | 搜索、读取、计算、制作、发布等真实动作 | 决定长期内容世界或营销立场 |
| 权限与约束 | 哪些动作允许、哪些需审批、哪些不能做 | 用大量禁止句控制创意判断 |
| 评测与反馈 | 是否真的完成目标、成本和错误在哪里 | 自动把一次成功升级成通用真理 |

这八项共同组成 Agent。增加 SOUL 只能补“身份与使命”，不能替代其余七项。

## 3. SOUL 的真实作用

`SOUL.md` 不是 Agent 的资格证，也不是魔法脑。Codex 没有使用这个文件名，仍然是完整 Agent；Hermes 使用它，
是为了把身份从项目规则和记忆中独立出来。

一个合格的身份资产只回答：

- 我与用户是什么关系；
- 我长期负责什么结果；
- 我如何使用判断和主动性；
- 我的表达气质与价值取向；
- 面对不确定性和不可逆动作时如何处理。

它不应包含：平台规则、黄金礼品答案、固定起号步骤、工具清单、每轮输出模板、评分公式、用户具体资料。

因此，第六版需要的不是“补一篇很长的 SOUL”，而是把现有短内核变成**独立、版本化、可检查的产品身份层**。

## 4. 谁负责思考，谁负责确定性

模型负责开放世界判断：

- 理解用户真正做什么；
- 判断目标受众和内容机会；
- 联想、解释、提出假设和创意；
- 在多个证据和方案间取舍；
- 决定是否需要搜索、Skill 或子 Agent。

代码负责确定性事实：

- 用户、项目、账号和数据所有权；
- 凭据隔离与权限；
- 审批、费用、发布、删除等不可逆边界；
- 状态机、版本、哈希、幂等与并发；
- 工具输入输出校验、回执和错误恢复；
- 指标计算与可重复评测。

判断不应被代码里的行业关键词硬门替代，安全和一致性也不应只靠 Prompt 请求模型自觉。

## 5. 单 Agent 与多 Agent

多 Agent 不是“更像公司”就自动更聪明。增加子 Agent 会增加上下文复制、协调、延迟、成本和分歧。

默认模式应是一个 Lead：

- 对用户关系和最终判断负责；
- 能动态发现并调用 Tool、Skill 或有界子任务；
- 收敛所有中间结果；
- 只有它能把建议变成项目状态或外部动作。

子 Agent 适用于边界清晰、可以并行、结果能独立验证的工作，例如资料检索、代码审计或对多个样本分别提取。
不适合把“受众、内容根、形式、变现”固定拆给四个平级角色再投票，因为这些判断相互依赖且需要同一个上下文。

## 6. 知识库、Skill 与 Memory

- **知识库**解决“有哪些可查事实或参考资料”。
- **Skill**解决“遇到某类任务，可以采用什么方法或程序”。
- **Memory**解决“从过去真实交互中，哪些稳定信息值得未来继续使用”。
- **项目台账**解决“这个用户、这个项目现在真实处于什么状态”。

它们不能混用。行业案例放 Skill/案例库，用户确认的账号方向放项目台账，用户长期偏好放用户档案，已验证的
跨项目经验经过审查后才可进入 Memory。聊天历史不是业务真相，模型推断也不能自动变成用户事实。

## 7. Agent 是否合格看结果，不看表演

合格标准不是“用了几个工具”“展示了多少思考”或“按几步执行”，而是：

- 是否正确理解当前任务；
- 是否在允许范围内主动完成可完成的工作；
- 是否产生真实、可用、可验证的结果或工件；
- 是否没有虚构事实、动作和回执；
- 是否在新证据出现后能够修正；
- 是否把不可逆决定交给正确的人；
- 是否能解释模型当时看到了什么、调用了什么、改变了什么状态。

这也是第六版后续“正经 Agent”验收的第一性标准。
