## 失败机制

### 1. 两个读者都越过内容根，提前写内容地图

`object_activity` 和 `human_practice` 没有形成少量同层候选，而是分别铺开场景、仪式和事件：

- 儿童绘本书架变成“亲子睡前共读、阅读角布置、绘本漂流、兄弟姐妹绘本传承”；
- 宠物殡葬变成“骨灰寄存、纪念饰品、忌日活动、哀伤辅导”；
- 祭祀鲜花变成“清明扫墓、中元祭祀、冬至祭祖、墓园空间”。

这些可以是冻结内容根之后的地图节点，却不是供上游比较的同层内容根。分工增加了发散量，没有提供层级判断。

### 2. 单工作者也把根识别和地图扩张混在一起

单工作者在登山杖中返回阿尔卑斯、安纳普尔纳、熊野古道和太平洋山脊步道，在狮子头中返回周恩来国宴、
《随园食单》和江南婚宴。它较多召回了正确语义方向，但输出已是人物、作品、地点和事件节点，不是同层根候选。

### 3. 语义路径合同造成大量不可修复丢失

七个双工作者案例和四个单工作者案例因 `semantic_path` 末端没有逐字等于候选标签而在代码绑定时失败。
结构化解析已经成功，错误发生在模型调用后的业务校验，因此现有修复器没有机会纠正；运行器也没有保留失败草稿，
只能保留错误类型。这是实验可观测性缺陷，也说明不应让模型重复填写可由代码推导的路径端点。

### 4. 无证据事实侵入候选理由

模型在关闭联网时仍写出孕期疼痛比例、路线长度和海拔、响应时限、历史人物与菜品来源等具体断言。部分可能真实，
但本轮没有证据来源，不能进入事实字段。双工作者没有改善事实边界。

### 5. 分离注意力不是营销判断

两个互不可见读者证明了并行发散可以产生更多角度，却没有回答“哪个语义层级能成长为长期内容世界”。多 Agent
本身不会补出这个判断，继续增加角色只会把内容根、内容地图和选题再次混成一层。
