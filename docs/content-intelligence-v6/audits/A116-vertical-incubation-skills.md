# A116 行业孵化知识从通用主脑拆分

- 日期：2026-08-20
- 状态：首个行业 Skill 已实现并通过真实黄金礼品验收；性能债未解决
- 触发问题：黄金礼品在多轮通用提示修补后仍反复被婚礼、三金、彩礼和抽象礼制吸走；修一类业务又会影响水果、海鲜、火锅和旅行。

## 病根

A115 证明了对标、版本、确认和下游工件可以工作，但首次内容根仍停在“礼如何规范行为”。本轮又用真实运行确认了三个独立缺陷：

1. 行业知识只作为候选时，通用根裁决会把它改回更窄或更抽象的高频答案。
2. 只在内容地图拦截局部场景时，账号路线模型会从自己的常识再次补回同一场景。
3. 只写“不得假设能力”仍可能产生“经营该业务意味着接触大量案例，但尚未确认”这种先编造后否认的句子。

因此行业边界必须是可版本化、可检查、贯穿下游的结构化合同，不能继续向通用提示词追加行业示例。

## 实现

通用 Lead 只保留领域无关的发现动作：起号请求最多描述并加载一个匹配的 `incubate-*` Skill，再把精确 Skill 名交给 `develop_account_strategy`。用户原话不变，Skill 正文不会拼进 `user_request`。

每个行业 Skill 可拥有不超过 16 KB 的 `references/incubation-profile.json`：

- `candidate_paths`：行业可复用的语义路径。
- `default_root`：可选的版本化默认内容根，只控制该 Skill 本轮候选地图。
- `branch_only_markers`：只有用户当前业务表达显式提到时才激活的局部场景。
- `do_not_assume`：不能从经营身份推导出的经验、案例、素材或能力。

Profile 必须来自一个已启用的精确 Skill，名称、Schema、大小和包内路径全部校验；未知、禁用、冒名或路径逃逸失败关闭。

边界传播为：

```text
Skill Profile
-> 内容根候选与可选默认根
-> 地图输入 excluded_local_branches
-> 地图输出确定性过滤
-> IncubationBrief.excluded_content_branches
-> 路线模型 content_branch_boundary
-> 持久化前禁止重新引入
```

用户明确提到相应场景时，该 marker 不进入排除列表。因此这不是总系统黑名单，也不会妨碍真正经营该场景的用户。

## 首个 Skill

`incubate-gift-human-relations` 的版本化路径为：

```text
礼品 -> 送与收 -> 人情往来 -> 人与人之间的相处与人情世故
```

当前默认内容根为“人与人之间的相处与人情世故”。它不决定账号路线；定位、受众、人设、表现形式和变现仍由账号孵化判断提案并等待用户确认。
