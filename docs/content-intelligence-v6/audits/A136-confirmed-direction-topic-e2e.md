# A136 已确认方向到具体选题的真实端到端审计

## 验证目标

验证 A135 之后的真实业务链，而不是只验证函数或结构化合同：

```text
黄金礼品的既有项目
-> 用户已确认“人情关系世界向”
-> 冻结内容根“人与人的关系本身”
-> 内容地图
-> 公开人物与真实事件取证
-> TopicBrief
-> MessagePlan
-> BaseDraft
-> Lead 可见答案
```

本轮固定用户请求为：沿刚确认的方向给出一个今天可直接拍的具体选题；表面不得讲黄金或礼品；必须使用
真实公开的人物和事件讲清一种人情世故，并给出核心观点和可拍稿。父级方向工件为
`artifact_3479ed45a096b0f79b4ba5805c39fcf09046659cee7c9d2cb39acac82b804e02`。

## 发现的断链

1. 旧方向只有一段较长的 `long_term_content_subject`。内容工具会把整段说明重新当作商业表达分析，已确认
   的内容根在后续轮次仍可能被重新选择。
2. 用户在当前轮明确提出的“真实人物、真实事件、排除黄金和礼品”只停留在 Lead 层，没有完整进入命名
   召回、证据阅读和选题收敛。
3. 工具未形成选题时，Lead 仍可能绕过失败回执，调用通用搜索并依据地图自行补稿。
4. 候选只需与宽泛地图维度相关，没有严格兑现末端路径，因此会把相邻家庭关系、学术理论或一次发表行为
   包装成目标事件。
5. 候选身份会提前夹带日期、数量、动机与结论；搜索结果又受前三条截断影响，直接原因常被低质量转述
   覆盖。
6. 编辑解释会被改写成人物本人的判断，或者把两项事实拼成“不是 A 而是 B”的排他性动机。
7. 交付层曾用“未核实内容未写成事实”概括限制，但实际成稿仍可能包含待核解释，回执过度乐观。

## 本轮最小修复

- 方向候选新增可空的精确 `content_root`；旧工件使用有界兼容提取。确认方向下的具体选题跳过内容根重选，
  直接冻结该值。
- 当前用户请求以 `instruction_not_evidence` 投影到召回、证据阅读和选题编辑；它约束对象类型、问题角度和
  排除项，但不能充当事实或搜索结果。
- 候选必须兑现地图末端路径；人物、事件按通常含义核对，相邻路径不能静默借用。
- 候选身份只保存最小稳定专名，首条查询表达一手讲述、原始作品、档案、公共机构或可靠报道等来源意图。
- 来源直接解释行为原因时必须优先采用；创意解释不能替换直接原因，也不能冒充人物本人动机。
- 核心事件或核心机制仍未核实时，限制说明不能把它包装成可拍选题，编辑器必须弃权。
- Lead 收到失败回执后不得另走通用搜索或依据地图补写；排除项约束整段可见答案，包括标题、前言和商业
  回桥。
- 交付回执改为明确提示“拍摄前逐项核对”和“不要写成确定事实”。

## 来源质量复核

第四次运行的题材本身可用，但现役检索只选中了搜狐、知乎等二手页面。独立人工核查找到了北京市委统战部
和人民网党史频道的公开材料；其中直接解释了分年付款是一种照顾章士钊生活、同时顾及其接受方式的安排。
这与“故意不一次还清以维持年度联系”的戏剧化推断不是一回事。该案例证明来源排序和直接原因优先级会改变
中心机制，不只是补一条引用。

## 当前结论

本轮采用的是方向继承、请求约束贯通、路径兑现、归因边界和失败关闭修复；不采用“只要地图正确就允许 Lead
继续写”的旧行为。当前系统已经从“会编出一条看似完整的答案”进步到“证据不足时会停”，但还没有稳定达到
“用户不提供线索也能自动找到一条可靠人物事件并交付稿件”。

下一步不应继续往核心提示词堆行业例子。需要单独验证研究层的候选替补机制：证据阅读应在预算内比较多条
真实路线，首选路线无法支持人物、事件和机制时，允许回到已取证候选池选择次优路线；每次切换都保留回执，
不能让 Topic Editor 静默改人、改事件或改路径。该机制通过新的冻结案例与真实运行前，不宣称完整业务闭环
已经验收。
