# A122 叙事骨架下游接线与真实故事回归

- 日期：2026-08-21
- 状态：adopted for first-incubation canary
- 上游：A121、ADR-035
- 代码基线：`9fa753ee`
- 模型：`glm-5-2-260617`
- 思考：关闭
- 温度：0

## 问题

黄金礼品已能将内容根冻结为“人与人之间的相处与人情世故”，但下游仍会把人性、分寸与
关系写成抽象说理。追踪发现，`TopicBrief.narrative_frame` 已经封存主角、目标、阻碍、行动、
代价和结果，但 `_render_delivery_input()` 没有将它传给 `MessagePlan` 生成器。上游即使找到故事，
下游也看不见。

## 测试先行

先增加两条失败验收：

1. 有证据的叙事骨架必须完整进入交付编辑的模型输入。
2. 交付编辑必须先让观众看到人物行动和变化，再显出道理；没有叙事骨架时不得硬编。

失败基线为 `2 failed, 9 passed`，两条红灯分别指向叙事字段缺席和编辑指令缺席。修复后
`backend/tests/test_content_intelligence_delivery.py` 为 `11 passed`。后续为题眼实体合同和行业分支接线
增加失败测试；内容地图、研究与故事交付三文件回归为 `100 passed`，内容工具、孵化、
研究与合同宽回归为 `183 passed`，行业 Skill 边界回归为 `104 passed`。

## 实现

- `SHOOTING_DELIVERY_INPUT` 新增可空“叙事骨架”投影，传递主角、具体目标、阻碍、行动或选择、
  失败或放弃的代价、结果或变化、证据引用和限制。
- 有骨架时，`opening + message_beats + closing` 要按事件发生顺序推进，道理在人物选择产生
  结果后再点破。
- 禁止用“先看、再看、这说明”将故事压回案例分析；禁止把证据没有的内心活动和单一因果
  写成事实。
- 没有 `narrative_frame` 的说明、比较、知识和历史梳理题保持非叙事，不增加故事配额。

## 真实模型运行

### 用户题设情景

以用户给定的“小王送得贵、小张送得便宜，后来小张升职、小王被边缘化”作为明示情景演绎。
叙事骨架已能进入稿件，但模型仍补入了题设没有的送礼动机和接收者内心活动，并在故事梳概后
退回说理。该运行为 **partial failed**：`17.381s`、1 次调用、`3538 tokens`。这说明单靠一条“讲故事”
指令不足，也不应该为了戏剧性伪造真实案例。

### 埃文·凯尔证据故事

改用新华社、云南人大网和国家保密局门户的有界公开证据，封存“收到相册、史料价值与地点待考、
更正表述、联系领馆、无偿捐赠、中方回赠、后续交往”行动链。真实 GLM 运行产出：

> 一个典当店从业者收到一本旧相册……埃文·凯尔做了一个不同的选择：他要为这本相册找到它该去的地方。

稿件随后按不确定性、更正、捐赠、回赠和关系变化顺序推进，最后才收束为“礼物的分量不只来自
价格，还来自对归属和关系的理解”。运行为 **passed for local canary**：`38.794s`、2 次模型调用、
`8547 tokens`，产物为 `message-plan-8d4088cb553e3fe6` 和 `base-draft-633770354e1d62dd`。

## 自动研究故障与恢复

同一事件的完整自动研究运行没有进入 `TopicBrief`。网页正文的 Jina 兜底未配置密钥且连接超时，
但程序已回退到搜索摘要。真正的终止原因是命名召回和证据阅读对“埃文凯尔 / 埃文·凯尔”的实体字面不一致；
一次有界修复后，阅读又将实体观察绑到另一候选的证据，严格合同以
`evidence reading grounded the selected candidate entity with another candidate's evidence` 拒绝交付。

进一步诊断发现三个独立问题：

1. 命名召回会把“埃文凯尔向中国捐赠相册事件”整句填入人物字段。现在题眼已点名对象时，
   `candidate.entity` 只复制最小完整专名，事件、动作和意义进入关系与查询字段。
2. “埃文凯尔 / 埃文·凯尔”只允许 Unicode 空格和中点类排版差异归一。真正换人、换事件仍会失败，
   不使用模糊字符串匹配洗掉实体边界。
3. 旧已确认地图只有饭局、随礼、借还、亲戚与职场等日常分支；现役根裁决虽明确提到公共礼仪与
   跨文化馈赠，行业 Skill 的 `supporting_branch_hints` 却未传给冻结地图生成者。现在只将这些
   可拒绝软候选传入地图，Skill 身份、版本、路由、验收和根偏好仍被隔离。

修复后的真实下游运行从已冻结且通过的“人与人之间的相处与人情世故”根开始。新地图保留“公共礼仪与
跨文化场合中的人际行为”；命名召回两条“埃文凯尔”路线，证据阅读收敛到捐赠、回赠、珍视与来华探访。
本轮公开摘要不足以支持当事人内心目标与阻碍，因此 `narrative_frame` 正确保持 `null`；交付层仍沿已证实的时间顺序自然讲完
“买到相册 -> 捐赠 -> 回赠 -> 保存与探访”，最后才收束为“有些关系不是靠等价还清，而是靠记住”。

该下游运行为 `223.324s`、7 次模型调用、`36866 tokens`，产物为
`message-plan-1e93ae16138d03f9` 与 `base-draft-9ad9ee66c93ea443`。正确性通过，但自动搜索来源质量低于手工有界证据包，
且发生两次交付修复。该数据是“首次孵化调试 + 新地图 + 自动搜索 + 选题 + 成稿”的冷启动回执，不是稳态单条内容成本。
之后的单条选题应复用已确认的定位、内容根、地图和计划，只追加当日题眼、证据、稿件与回执；需要另行测量这条增量路径，不能用本轮数据推断每条都会同样消耗。

## 运营时间层

- **首次孵化**：建立业务理解、内容根、候选地图、定位、受众、人设、表现形式和变现假设，允许较重的一次性研究。
- **7 天 / 30 天运营计划**：根据已确认方向与用户产能，给出频率、栏目组合、具体题目、表现形式和观察目标。这是可调整计划，不是写进核心提示词的固定流程。
- **日常增量生产**：从内容地图、用户亲历案例、公开热点、新证据、对标观察和旧内容反馈中抽取一个具体切口，生成 `TopicBrief -> MessagePlan -> BaseDraft`。
- **周期复盘**：根据真实发布数据、评论、受众变化和用户新资源更新地图与计划。地图是可持续探索的版本化资产，每个已交付选题仍绑定当时版本以保留因果与证据谱系。

## 结论

“内容根 -> 内容地图 -> 取证选题 -> 可空叙事骨架 -> MessagePlan -> BaseDraft”的故事接线已打通。
这不是新增一个常驻编剧 Agent，而是修复已有工件之间丢失的信息，并让行业 Skill 的可拒绝分支提示真正到达地图生成者。
当前已验收手工有界证据故事和从冻结根开始的自动搜索故事；尚不宣称性能合格，也不将缺少行动骨架的说明题强迫改写成故事。
本轮只记录首次孵化冷启动上界；稳态的日常选题速度与成本必须用复用已有地图的独立运行验收。
