# A82 首次项目自举、经营容器内容根与续写串线审计

## 审计状态

- 日期：2026-08-18
- 基线：`a1ac5177`

- 范围：未选择项目的首次起号、经营容器与被服务对象的根选择、同会话已确认路线的续写边界

## 用户验收问题

用户在普通新会话直接输入：

```text
我是开水果店的，我要怎么起号
```

产品入口没有项目选择器，也不应要求用户先绑定或登录平台账号。首次回答应先形成可审阅的账号路线，
而不是要求用户理解内部项目台账。水果店是经营容器；内容地图需要比较门店经营与“水果”本身的长期
内容容量，不能因为买卖发生在店里就把门店交易场景提升为整张地图。

## 第一处失败：内部项目成为用户硬门

首次真实页面回答直接要求“先创建或选择一个项目”，没有运行语义、内容地图或账号路线。追踪发现
`develop_account_strategy` 无条件要求运行上下文已有 `incubation_project_id`，而普通前端没有项目选择器。
A80 的“无平台账号也能起号”验收预先注入了项目，因此没有覆盖真实首次入口。

修复后，账号策略工具在身份、线程和运行均可信但没有显式项目时，按 owner 与 thread 生成稳定的隐式
项目引用，并在第一次真实孵化请求时惰性创建。显式选择但已失效的项目仍拒绝；隐式项目一旦存在，
Gateway 在后续运行把它写回线程 metadata 并重水化到运行上下文。该行为只省去内部建档步骤，不省略
所有权、项目台账或产物谱系，也不涉及平台账号。

## 第二处失败：门店买卖冒充水果世界

项目自举后的第一次真实完整链正确识别：

```text
offering_role: operating_container
served_objects: [水果]
content_entry: 水果
```

但根裁决选择了“人们聚在固定场所买卖水果”。病根不是用户信息不足，而是共同世界合成把无修饰词
“店”的泛化活动“买卖”重新加上“水果”，生成一个看似有参与者的长标签；候选构造器又把它当作比
“水果”更大的社会世界。后续三条账号路线因此全部围绕门店交易、熟客和价格展开。

确定性修复只处理这一结构关系：当商业对象是经营容器、存在完整被服务对象，且共同世界的核心动作
精确复读无修饰容器的泛化经营动作时，该共同世界降为被服务对象旁边的具体场景分支，不能竞争地图根。
规则不含“水果店、药店、买卖”等行业关键词。留出回归使用药店/药品；KTV 没有独立被服务商品，唱歌、
社交和情绪释放仍可形成有效根候选。

## 修复后真实结果

同一线程再次运行时，根裁决明确选择“水果”，并给出反向包含判断：水果店只是水果世界中零售分支的
一个节点；品种、产地、季节、人物、历史和文化不能被门店场景覆盖。冻结地图形成品种选育与消亡、
产地风土、季节物候、果农劳动、流通价格、感官认知、驯化史和地方饮食文化等方向，随后生成具体选题：

```text
阳光玫瑰葡萄从998元一串跌到5元一斤，品种本身没有变，变的是什么？
```

这证明本轮经营容器根修复在该真实样本上有效，但不能把整轮记成“首次起号通过”。

## 第三处失败：旧确认状态把起号请求改成续写

本次复跑沿用了同一线程和隐式项目。上一轮已经确认“季节周期记录者”，Lead 因此没有重新调用账号路线
提案，而是把用户再次输入的“我要怎么起号”解释成“沿已确认路线生成第一条具体选题”。工具随后继续
完成联网取证、证据阅读、TopicBrief、MessagePlan、BaseDraft、表现形式和适配稿。

该行为违反当前请求优先原则，也使本次运行失去干净首次起号评测资格。后续必须显式区分：

1. 首次起号或当前没有提案：生成路线并停在用户选择。
2. 用户明确要求沿已确认路线继续：生成一个具体选题或下游内容。
3. 用户明确要求重新定位或重新评估：生成有修改原因的后继提案。

不能仅因项目里已有确认版本，就把重复或重新提出的起号问题自动改写为下游制作任务。本轮只登记问题，
尚未采用新的分类器、提示词硬门或工作流。
