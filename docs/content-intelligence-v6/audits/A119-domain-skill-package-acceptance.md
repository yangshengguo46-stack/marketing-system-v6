## 为什么补这一轮

A118 已把 Profile、版本和评测类型接入运行时，但独立复核发现验收只绑定 Profile。若有人只改
`SKILL.md` 的触发描述或正文，旧回执仍会被接受；`evidence_ref` 也只是一个没有验证的字符串。
第一轮把四个模型输入组件纳入摘要后，第二次独立审查又证明回执正文仍可改成 `trust me`、证据可指向
不存在的路径、时间也可填任意文字。这会让真正影响模型的内容绕过重新评测。

## 完整激活包

现役行业 Skill 的激活摘要同时绑定：

1. 模型可见的完整 `SKILL.md`。
2. 类型化 schema-v2 Profile。
3. trigger、anti-trigger、behavior、held-out 四类评测定义。
4. 标准正/反触发集。
5. 带时区时间、逐 case 结果和限制项的包内验收回执。
6. 位于 `evals/evidence/`、由回执记录 SHA-256 的包内精简证据。

`package_sha256` 只排除 manifest 与回执中的自身字段以避免循环，其余内容任何一字变化都会令旧验收
失效。通用 Skill parser 与 Profile loader 共用同一个证据校验器；二者都会要求包内
`evals/acceptance.json` 存在、版本与摘要一致、逐项覆盖评测 manifest 的精确 case id，且没有 failed
或 not_run。证据只能用回执相对路径指向自己的 `evidence/` 子目录，运行时同时验证文件存在、不能越界
以及内容哈希一致。它不能证明外部世界的结论绝对正确，但能阻止旧回执、空路径和改后未复验的包被误激活。

## 否定作用域

局部分支激活不再依赖几条完整固定句式，而是在当前分句内识别否定或排除作用域。冻结回归覆盖“不做”、
“无关”、“非业务”、“没关系”、“别讲”、“不想碰”、“不要讲”、“别往上扯”、“完全没关系”、
“不是做”、“不在业务范围内”、“没有任何关系”和“压根不碰”十三种表达。正向对照同时覆盖“别墅婚礼”、
“非遗婚礼”、“不只是做婚礼”和“不是唯一业务但确实是主营”，避免用一个宽字符窗口误伤真实业务。它只
决定某个局部分支有没有被用户实际业务激活，不参与内容根或营销判断。
