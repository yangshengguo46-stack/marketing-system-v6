# A58 有界并行语义工作者审计

## 问题

语义理解、词义家族、共同世界、反事实复核、内容根和地图原本形成六次串行模型调用。
真实案例通常需要数分钟，且中间工作者反复重述同一语义，既增加延迟，也使后一个提示词容易
覆盖前一个判断。用户要求使用多智能体提速，但内容根又必须保持唯一裁决，不能让多个自由 Agent
同时修改业务状态或各自给出最终答案。

## 方案比较

1. DeerFlow `task` 子 Agent：适合独立研究和大样本对标，但返回自由文本，带工具、中间件和上下文
   开销，不适合紧耦合的结构化语义中间态。
2. 六个原工作者全部并发：根裁决依赖候选，地图依赖冻结根，违反数据依赖，也会产生互相冲突的根。
3. 两个首轮只读工作者并发：业务语义和词义世界都从用户原表达独立读取，随后由确定性代码合流；
   单一根裁决器和地图继续串行。该方案保留数据依赖，同时减少关键路径。

## 已实现架构

```text
用户原表达
-> 并行：业务语义阅读 | 词义世界阅读
-> 确定性合流、词法范围与构成语境校验
-> 单一内容根裁决
-> 只看冻结根的账号级内容地图
```

- 首轮两次结构化调用用 `asyncio` 同时启动，互相看不到答案，也不能调用工具或写状态。
- 词法主词完全一致时直接合流；一个主词是另一个在原对象中的连续嵌套范围时，只保留两边都
  成立的意义成分；无包含关系时撤下词义世界并记录未知。
- 可选词义证据只在合流时校验模型候选，不把词典当答案注入模型。
- `context_bound_worlds` 将构成修饰语绑定到完整对象、活动、事件、人群处境或关系世界。
  候选若没有保留全部 `required_contexts`，确定性代码在地图调用前拒绝它。
- 根裁决器只能从冻结候选索引中选择；地图只接收已经冻结的内容根。
- 正常路径由六次串行调用降为四次调用、三个关键阶段。

## 测试证据

- 并发屏障测试要求两个首轮工作者同时到达；若退化为串行会超时失败。
- 测试模型改为每次结构化绑定返回独立包装器，避免共享 `current_schema` 在并发下造成假绿。
- 覆盖首轮取消、可选词义工作者失败降级、嵌套词法范围、不相干主词撤回、构成语境绑定、
  丢失语境的根拒绝和地图只见冻结根。
- 删除旧串行实现后，七个相关聚焦套件最终为 `120 passed in 5.03s`；Ruff 与
  `git diff --check` 均通过。

## 真实回归

- “折叠雨伞”收敛到“日常出行防雨”，约 `88.78s`，通过。
- “乔迁礼物”收敛到“乔迁庆祝”，成功运行约 `87.04s`；能识别生命事件，但关系世界仍有提升空间。
- 第一轮“拳击手套”错误扩大到“搏击实战与对练”，约 `101.79s`。该失败暴露候选虚假继承
  `拳击` 构成语境的问题。
- 增加显式语境绑定后，同一案例收敛到精确内容根“拳击”，约 `101.44s`。地图耗时约
  `61.84s`，成为当前主要延迟来源。
- 一次“黄金礼品”回归已脱离黄金材质并到达“礼赠”，但没有继续到“礼、人与人相处与人情世故”，
  记为部分正确、严格不通过。该结果不允许被包装成语义内核已经完成。

用户在 2026-08-17 决定将当前结果冻结为可用检查点，不再为追求最优语义架构阻塞下游具体选题。
因此 A58 的采用含义是“当前可用并进入下一模块”，不是所有语义金标已经通过。

## 边界与后续

- 多工作者是延迟优化和注意力隔离，不是质量投票；最终只有一个内容根裁决器。
- 进程级结构化调用并发保护仍需与 DeerFlow 已有 LLM 限流、重试和熔断边界统一后压测。
- 地图调用仍需在不损失长期内容丰富度的前提下缩短输出与等待时间。
- “黄金礼品”修正必须使用通用语义测试和非黄金反例，禁止写行业标准答案或再加一层固定流程。
- MediaKit 继续作为对标和素材证据感知底座，本切片没有冻结或修改 MediaKit。
