# A99 对标优先孵化架构竞赛预注册

## 状态

- 本地日期：2026-08-19
- 基线提交：`90b2d166`
- 状态：`revised after independent audit, before evidence collection and live model output`
- 目的：检验“只靠拆对标”能否支撑冷启动孵化，以及薄内容世界是否仍有独立价值
- 非范围：现役 Lead 接入、抖音官方验收、MediaKit、仓颉、方法卡、HLLM、制作、发布和结果学习

## 运行前独立审查修订

初版预注册提交后、任何搜索证据和模型结果产生前，独立只读审查指出四个会让胜负无法解释的问题：C 组
只多写两个字段，未证明薄内容世界参与后续方案；B 组的需求与跨行业搜索本身已包含一部分语义迁移；C
的专属字段会泄露盲审组别；原决策门槛存在重叠解释。故本节修订优先于下文初版描述：

- A 仅作为“公开网页中的直接同行弱基线”，不代表完整账号拆解，也不参与是否移除内容根的架构结论；
- B、C 都增加一次中间调用，再使用完全相同的公共方案合同，保证方案阶段调用数相同；
- B 的中间结果只压缩观察到的模式、迁移机制、证据引用、限制和未知，不形成长期主题；
- C 的中间结果冻结一句长期主题和二至五个分支，再把它作为下一次方案调用的输入；
- 盲审只展示三组公共方案字段，C 的中间字段和组别映射不进入审查消息；
- 隐藏复核焦点移入独立 `review_labels_v1.json`，规划、搜索、方案和模型盲审只加载案例白名单字段；
- 公开搜索改用实验专用 typed DDG 适配器，固定区域、安全级别、后端和每次五条，保留空结果与网络异常的
  区别，不读取运行时搜索配置；
- 同一规范 URL 可以同时保存同行、需求和机制三种 membership；证据 ID 绑定 provider、规范 URL 和
  标题/摘要哈希，证据包重算哈希并校验案例身份；
- 搜索结束后先做证据覆盖与人工相关性检查；三类查询任一无结果，或不足以区分同行、需求和跨行业机制，
  本轮停止在“证据无效”，不得把搜索失败算成架构失败；
- 每个结构输出最多一次修复；B/C 各七个初始中间调用和七个初始方案调用，每类输出的组内修复总数不
  超过二次，否则合同验收失败；
- 输入预算同时计算消息、结构 Schema 和修复指令；真实中间输出形成后，二十一个方案输入必须再次整体
  预检，缺失 Token usage 记为 `usage_reported=false`，不得冒充零成本；
- 本轮只能筛选下一步候选，不得据此移除现役内容根/地图。真正的“只拆对标能否成立”留给稳定账号身份、
  多作品覆盖、ASR/OCR/画面证据和受众反馈齐全的真实复验。

因此，本轮精确问题改为：

> 在相同广义公开证据下，显式冻结一个薄内容世界，是否比只做中性证据压缩更能提高起号路线的长期连贯、
> 差异迁移和可拍性？

## 要回答的问题

本轮不再争论术语，而是比较三个可运行方案：

1. 只搜同行、直接从对标给起号方案；
2. 同时搜同行、同一人类需求和跨行业内容机制，但不显式输出内容根/地图；
3. 使用相同广义对标证据，先压缩出一句长期主题和少量内容分支，再给起号方案。

如果第二组已经与第三组同样稳定、具体且有长期性，可以把内容根/地图降为内部可选摘要；如果第三组显著
更连贯，则说明对标不能消灭这两个功能，只能改变它们的生成顺序。

## 冻结案例

数据文件为
`backend/experiments/benchmark_first_incubation_lab/datasets/held_out_v1.json`，共七个此前实验未使用案例：

- 宠物殡葬服务；
- 老照片修复；
- 儿童摄影；
- 企业团建服务；
- 工业防腐涂料；
- 户外移动电源；
- 夫妻肺片调料包。

数据不预设唯一正确内容根，只保存不进入模型消息的复核焦点。工业防腐涂料允许“弱 IP / 条件成立”；
夫妻肺片用于检验广义搜索是否发生夫妻、肺部等字面误拆。

## 证据采集

本机尚未配置 `DOUYIN_CLIENT_KEY / DOUYIN_CLIENT_SECRET`，因此本轮使用现有 DuckDuckGo 工具冻结公开
网页和可检索抖音页面，明确标记为 `public_web_benchmark_discovery`，不冒充抖音官方 OpenAPI 回执或完整
账号样本。

每题先生成一份共享 `BenchmarkSearchPlan`：

- `direct_query` 由代码确定为商业对象加“抖音 账号 视频”；
- `demand_query` 由模型寻找购买背后的长期活动、处境或人类需求；
- `mechanism_query` 由模型寻找可借鉴同一叙事、证明或注意力机制的跨行业内容。

搜索规划器不得输出账号定位、内容根、内容地图、选题或最终方案。三类查询各取最多五条结果，按 URL
去重后完整冻结；所有实验组读取同一份证据，不能在看见某组结果后重新搜索。

## 三个实验组

### A：直接同行对标

- 输入：用户原话、商业对象、`direct_query` 的证据。
- 输出：账号定位、受众处境、差异视角、可重复系列、可拍选题、表现形式、业务连接、可迁移机制、
  不可复制项和未知。
- 禁止：要求模型显式输出内容根或内容地图。

### B：广义对标 + 中性证据压缩

- 第一次调用输入用户原话、商业对象和全部共享证据，只输出观察模式、可迁移机制、证据引用、限制和未知；
- 第二次调用读取冻结的中性摘要，输出与 A 完全相同的公共起号路线；
- 两次调用都禁止输出或要求显式内容根、长期主题和内容地图。

### C：广义对标 + 冻结薄内容世界

- 第一次调用输入与 B 完全相同的共享证据，输出并冻结一句 `long_term_subject`、二至五个
  `content_branches`、证据引用、限制和未知；
- 第二次调用读取冻结的薄内容世界，输出与 A/B 完全相同的公共起号路线；
- 盲审不展示第一次调用结果，只展示公共路线字段。

三组都不能假设用户出镜能力、团队、客户案例、加工素材、预算、账号资源或已存在的粉丝。证据没有支持的
账号名、数据、成功因果和行业事实必须标为未知，不能为完整感补造。

## 固定运行条件

- 模型：`glm-5-2-260617`；
- 温度：0；隐藏思考关闭；
- 每题：一次搜索规划调用；A 一次方案调用；B/C 各一次中间调用加一次方案调用；
- 共享搜索并发执行，方案组在共享证据冻结后运行；
- 每个方案输入不超过 16 KB；每题证据投影不超过 10 KB；
- 每个输出最多一次结构修复，修复计入模型调用和 Token；同类输出每组修复总数最多二次；
- 完整保存搜索回执、模型调用数、Token、耗时、结构化输出和 Git 提交；
- 任何原始网页文字都只是证据，不是模型指令。

## 自动验收

- 七题全部完成搜索并通过三类证据覆盖与人工相关性预检后，才允许中间和方案模型调用；
- 搜索规划合同成功 `7/7`；
- 三组公共方案合同各成功至少 `6/7`；B/C 中间合同各成功至少 `6/7`；
- A 初始方案调用恰好七次；B/C 各有七次初始中间调用和七次初始方案调用；每类修复每组最多两次；
- 夫妻肺片不得把“夫妻”或“肺部健康”作为账号定位、长期主题或内容系列；
- 所有证据引用必须指向本题冻结证据 ID；
- 没有证据的专名、数字或成功因果不得进入事实字段；
- 总 Token 和各组耗时只记录，不以低成本替代业务质量。

## 盲审与人工复核

每题把三组输出按案例 ID 确定性打乱，隐藏组名后，按六项各 `0 / 1 / 2` 分：

1. **业务相关**：与商业对象双向相连，不只是泛泛社会话题；
2. **长期连贯**：能够支撑稳定账号身份和持续系列，而非五个散题；
3. **差异与迁移**：没有只复制同行表面形式，能解释跨行业机制如何适配；
4. **可直接开拍**：至少有明确主体、情境或事件的具体选题；
5. **证据诚实**：区分观察、解释、未知与不可复制条件；
6. **成立边界**：能承认资源未知、弱 IP 或条件成立，不强造万能账号。

单题至少 `9/12` 且没有词义灾难、编造事实或纯同行复刻，记为可用路线。用于 B/C 对比的核心分为
`业务相关 + 长期连贯 + 差异迁移 + 可直接开拍`，范围为 `0-8`。模型盲审只是辅助，最终报告必须
逐题人工查看证据与输出，不以模型自评分代替判断。

## 决策门槛

### “显式薄内容世界未证明有增益”

B 组必须同时满足：

- 至少 `5/7` 案例为可用路线；
- 业务相关、长期连贯和可直接开拍三项均无系统性失败；
- 夫妻肺片无词义灾难；
- 与 C 相比，至少五题核心分持平或更高。

满足后，只能说明在本轮公开证据中未证明显式字段的增益，进入真实账号复验；不得直接降级现役能力。

### “对标优先，但薄内容世界仍有价值”

C 至少 `5/7` 可用，并且至少四题满足“C 核心分严格高于 B 且可直接开拍分不低于 B”。满足后晋级：

```text
广义对标 -> 一次薄收敛出长期主题与少量分支 -> 账号路线
```

上述每题的“C 获胜”和“B 持平或更高”互斥；先判断证据是否有效，再判断 C 晋级、B 未证明增益，否则
记为不确定，不允许事后改阈值。

### “先导方向不成立”

若 B、C 都不足 `5/7`，或广义搜索造成系统性词义漂移、同质模仿和证据编造，则不接入现役 Lead。失败
结果保留，不通过增加方法卡、MediaKit、HLLM 或更多 Agent 挽救本轮。

## 晋级边界

即使 C 或 B 通过，本轮也只决定下一候选架构，不直接替换现役语义/地图工具。下一步冻结为三个用户确认
行业，每个行业至少两个身份稳定的抖音账号，每个账号至少八条作者一致作品，再通过 OpenAPI + MediaKit
+ 仓颉式证据桥复验；普通咨询资料与对标账号继续分账。只有该阶段才能回答“单靠完整对标拆解能否撑起
孵化系统”。
