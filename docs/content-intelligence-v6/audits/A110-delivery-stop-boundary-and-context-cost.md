# A110 交付停止边界、资源事实与上下文成本审计

## 研究问题

A109 已证明确认路线可以生成合格的具体选题，但一次请求仍自动经过表现形式、改写和制作规划，聊天中又
重复展示地图、策略、内容推进、证据边界和制作建议。结果是一次“给我一个今天能拍的选题”需要 8 次模型
调用、66,295 Token，并把用户没有声明的素材、客户案例和经营经验写成事实。本轮只处理三个问题：普通
选题请求应该在哪里停止，哪些资源可以进入下游判断，以及固定链路与历史会话各自消耗了多少上下文。

## 结论

普通具体选题交付现在固定为：

```text
content_reading
-> content_map_candidate
-> topic_brief
-> message_plan
-> draft_version
-> 停止并返回一个紧凑的“今日建议拍摄”
```

`FormatDecision`、`AdaptedDraft` 和 `ProductionPlan` 不是默认尾巴。只有用户明确要求表现形式、适配成稿或
制作方案时才继续，而且制作请求只是在代码中显式蕴含前两个下游步骤，不会改变已经封存的基础稿。

项目主体原话只证明“用户做什么”，不能证明用户做了多久、见过什么、经手过什么，也不能证明其拥有
门店素材、客户案例、库存、团队或出镜人员。形式决策中的每一项 `ResourceMatch` 现在必须至少引用一个
正式用户素材父工件；没有证据就保持未知，不能为了完整感补造。

## 失败测试先行

第一组失败测试固定以下边界：

1. 默认持久化只到 `draft_version`，不会创建形式、改写或制作工件。
2. 聊天只展示一个题目、一条内容路线、主体/情境/事件/立场/观点/切入点和一份基础稿。
3. 完整账号策略、候选地图目录、重复内容节拍和制作计划不进入默认回答。
4. `ResourceMatch` 没有证据父工件时 Schema 直接拒绝。
5. 交付提示明确禁止把业务身份改写成已有素材或经验。

第二组失败测试来自真实运行暴露的问题：

1. 确认路线后的“给我今天能拍的选题”不能被显示成账号主体；立场必须绑定原始项目主体原话。
2. 提供方返回字符串 `"null"` 时，情境应归一为空值而不是显示字面量。
3. 未取证的“我们客户”“店里待久了就知道”“经手过”等第一人称经验必须触发一次有界修复。
4. 证据外西里尔字母词必须触发同一事实边界修复。
5. 账号长期方向不再以大段自由文本重复出现在单题交付中。

两组测试均先失败再实现；最终跨模块聚焦回归为 `248 passed`。

## 真实运行回执

| 运行 | 模型调用 | Token | 结果 |
| --- | ---: | ---: | --- |
| A109 旧书确认路线旧实现 | 8 | 66,295 | 选题通过，成本、长度和资源边界失败 |
| 旧历史线程、默认止于基础稿 | 5 | 60,953 | 调用下降，首个 Lead 上下文仍达 29,620 Token |
| 全新线程、通过官方项目绑定接口续接 | 5 | 42,615 | 完整成功，只封存 5 个核心工件 |

相对 A109，默认模型调用从 8 次降至 5 次，下降 `37.5%`。相对同一停止边界的旧历史线程，全新绑定线程
总 Token 从 60,953 降至 42,615，下降约 `30.1%`。这说明两类成本必须分开：砍掉自动下游减少调用，
清洁线程和精确项目续接减少固定上下文。不能把两者都归因于模型。

第一次新线程探测错误地试图由调用方 metadata 写入保留的 `incubation_project_id`。Gateway 正确剥离了
该字段；该运行在验收前中止，不计入通过样本。随后改用正式项目绑定 API，服务端所有权投影和续接正常。

完整运行之后又针对最新事实边界复用已封存的阅读、地图、选题和策略工件，只重跑一次交付模型。该定向
验证不是第二次完整端到端，但确认了：账号立场恢复为“我是开旧书店的，该怎么起号？”，没有字面量
`null`、虚构经营经验、西里尔词或账号方向长段落；基础稿 1,216 字符，完整聊天投影 2,228 字符。

## 聊天投影与事实台账

详细证据、未知、限制、策略和模型中间合同仍保存在工件台账。聊天投影只显示数量状态和引用，不再复制
完整清单。已确认账号路线只显示路线名称和选项 ID，不把整份孵化判断塞入每个选题请求。

这不是删除能力，而是把“模型需要读取的事实”“审计需要保留的工件”和“用户此刻需要看到的回答”分成
三个投影。紧凑回答不能降低事实约束，详细台账也不能强迫每次都跑完整生产链。

## 尚未解决

- 全新线程仍消耗 42,615 Token，最大剩余成本来自证据召回、网页阅读和结构化收敛，不是表现形式或制作。
- 旧历史线程的 29,620 Token 首次 Lead 上下文属于单独的会话压缩和状态投影问题。本轮不在运行时做临时
  消息过滤，避免破坏 DeerFlow 的记忆、人工确认和工具调用连续性。
- 抖音官方搜索仍返回 `28001018 应用未获得该能力`。它只作为供应商回执保留，不再触发改请求代码或
  回退视觉网页采集。
- 当前回答仍显示证据边界和未知数量；是否进一步压缩要以跨行业可理解性测试决定，不能仅按字数删除。

## 验收结论

本轮达到 A109 指定的下一步：默认回答压缩为一个今日选题和基础稿，未知资源不再被写成事实，正常运行
只封存 `content_reading`、`content_map_candidate`、`topic_brief`、`message_plan`、`draft_version`。
下一轮应该单独优化证据阅读预算与会话状态投影，不能恢复自动形式/制作尾链，也不能再把所有模块塞进
一次用户请求。
