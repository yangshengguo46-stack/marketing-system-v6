# A33 可拍交付层回执

## 验收问题

内部的语义理解和内容地图可以宽广、学术和百科化，但完成探索后是否能交付一条具体可制作的内容。

## 失败基线

2026-08-16 首次真实白酒回归已形成以“宴请待客”为根的内容地图和一条满汉全席 `TopicBrief`，
但嵌套 `MessagePlan + BaseDraft` 合同在原始请求和一次修复请求中都没有收到可恢复的工具参数。
运行因此按合同回退为地图正文，没有把不可校验的交付展示给用户。

## 修正

- 模型只返回扁平 `MessagePlanDraft`。
- `BaseDraft` 由 `opening + message_beats + closing` 确定性组合。
- 模型不重复输出基础长稿，也不让另一次模型调用改写已审议结构。
- 结构字段固定为具体主体、可选情境、具体事情或问题、用户立场、观点、开头、无定额的内容推进与收束。

## 真实模型探针

### 扁平合同单独探针

- 模型：`glm-5-2-260617`
- 供应商思考：关闭
- 用户原话：“我是卖白酒的，该怎么起号？”
- 结果：一次调用通过，完整返回具体主体、宴席场景、地域饮酒问题、白酒经营者观察立场、中心观点与基础文案。
- 实测暴露了两个提示边界：不得从模型常识补仪式角色或步骤；用户的商业立场不得让文案结尾回到“消费者为什么买单”。

### 完整白酒端到端回归

- 模型：`glm-5-2-260617`
- 路径：Lead → `explore_content_world` → 语义 / 词义 / 内容根 / 地图 → 并行搜索 → 证据阅读 → `TopicBrief` → `MessagePlan` → `BaseDraft`
- 内容根：“以白酒为媒介的人情往来与礼数实践”
- 具体选题：“白酒送礼的价位阶梯与礼数编码”
- 结果：终端第一行为“今日建议拍摄”，后续包含谁、场景、事情、用户立场、观点、内容推进、基础文案、内容路径、证据边界、未知与参考资料。
- 来源限制：个人文章、行业营销文章和招商网站不能单独支撑价位、品牌与礼数的普遍判断。该回归只通过交付结构，事实内容仍是待核验候选。
