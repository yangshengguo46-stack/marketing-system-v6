# ADR-015: TopicBrief 之后的可拍交付层

## 状态

`reviewed -> adopted for local canary`

## 背景

语义理解、内容根、内容地图和根后研究本来就允许学术性、百科性和宽广发散。问题不在
探索过宽，而在系统把内部探索正文当成了账号用户最后的交付。用户明确了最小可拍结构：
“什么人，在什么时间或情境下，遇到什么事情，账号再结合用户的真实立场输出观点”。

## 决策

1. `ComprehensionRecord`、`ContentWorldView` 和 `TopicBrief` 保持原职责，不把内容地图改成拍摄模板。
2. 只有已经形成 `TopicBrief` 时，下游才可以请求一份扁平 `MessagePlanDraft`。它必须显示具体
   主体、具体事情或问题、用户立场和明确观点；时间、地点或场景只在对这件事有构成性时填写。
   ADR-016 进一步将切入口、讲述视角、观众问题、信息顺序和最终回报绑定到同一计划。
3. 用户立场仅由逐字 `user_request` 支持，不补造从业年限、客户案例、业绩、资质或素材。立场决定
   观察角度，不能代替事实证据，也不允许结尾自动回到购买、成交或“消费者为什么买单”。
4. `opening + message_beats + closing` 同时是一份形式无关的基础文案。代码确定性组合它们，
   不让模型再交一份重复长文，也不预设口播、出镜、短剧、图文或纯素材。
5. 有合格交付时，`explore_content_world` 优先返回“今日建议拍摄”，并显示一条内容路径、证据边界、
   未知和来源。无 `TopicBrief` 或交付合同失败时，保留原内容地图正文作为失败开放回执。
6. 编剧脑、口播、图文、纯素材和平台适配尚未进入本层。只有表现形式被选为叙事时，才能在
   `MessagePlan` 之后按需调用编剧方法。

## 被拒绝的方案

- 把“谁、时间、事情、观点”写进内容地图：会让发散地图过早收敛。
- 在一个嵌套 JSON 中同时交付 `MessagePlan + BaseDraft`：真实 GLM 连续两次没有返回可恢复的
  工具参数，而扁平合同单独实测通过。
- 将第四版的营销提示词、编剧提示词和硬门整体迁入：只允许后续按字段合同迁移可选能力。

## 验证与限制

- 新增交付与直达路由的聚焦测试通过；ADR-016 之后内容智能回归为 `93 passed`。
- 真实 GLM 扁平合同探针在一次调用中返回完整交付。
- 真实白酒端到端回归最终返回“白酒送礼的价位阶梯与礼数编码”，包含所有必要交付字段，
  且没有再输出长地图正文。
- 该白酒选题的资料主要来自个人文章和商业站点，系统已显示限制与未知，但这只能验收“从地图到
  具体交付”的结构，不能把其价位与礼数判断标记为生产可发。
