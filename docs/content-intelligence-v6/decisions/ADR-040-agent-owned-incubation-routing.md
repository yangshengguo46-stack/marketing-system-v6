# ADR-040 Agent 自主孵化路由

## 决定

默认 Lead 是唯一账号孵化判断者。起号和定位请求不再由固定工具拥有，也不再规定词项、受众、语义、内容根、
地图、对标和路线的必经顺序。Lead 根据当前问题和不确定性选择最少必要方法，并在当前范围内直接作答。

`develop_account_strategy` 从默认 Lead 工具目录移除，保留为历史数据和离线兼容实现。它不得通过 Prompt、
Skill 或中间件重新成为强制入口。

## 约束

- 先理解用户实际业务和目标；只有会改变路线的受众差异才触发一个有界澄清。
- 陌生词核实、Agent 产品档案、语义分析、内容地图和对标都是可选能力，不拥有最终判断。
- 同一用户轮次最多形成一份内容地图工作材料；已有结果后不得换措辞重算。
- 行业 `incubate-*` Skill 提供可拒绝的领域注意力，可在特定行业建议一种方法，但不能覆盖用户事实、
  编造资源或决定最终路线。普通对话不读取其治理和历史 Profile。
- 未陈述的场景、受众、渠道、形式、案例和能力保持未知。先断言、后表示不确定仍属于编造。
- 宽泛“怎么起号”默认只回答方向，不自动附加发布日历、频率、时段、比例、投流或 7/30 天计划。
- 合法动态工具链使用统一的 180 super-step 默认预算；重复调用检测、工具级幂等和服务端最大值继续生效。

## 未采用

- 不把旧受众优先合同删除；其数据区分仍有效，但不再是每次对话必须执行的工具阶段。
- 不把所有业务改成“先拆字”，也不让稳定词为了仪式感联网。
- 不用行业关键词黑名单修通用主脑；行业差异留在按需 Skill。
- 不把一次真实输出自动沉淀为通用规则或修改核心提示词。
- 不立即把动态聊天判断塞回旧 `IncubationJudgment`，因为该工件要求地图父级并会恢复旧顺序。

## 理由

真实运行证明，固定工具会重复提问并掩盖模型判断；完全删除方法又会让模型退化成通用模板。最小可用边界是
保留 DeerFlow 的渐进工具和 Skill，但让 Lead 决定何时使用。黄金礼品和企业答谢礼在全新线程完成了业务、
受众与长期内容世界判断，同时避免旧 Profile 和固定路线工具，足以接受该运行时权责调整。
