# ADR-033 行业孵化知识使用按需 Skill

## 决策

通用孵化脑只负责共同的阅读、候选比较、证据边界和最终收敛。行业特有的语义跃迁、常见局部场景和不可假设资源进入独立 `incubate-*` Skill，通过 DeerFlow 延迟发现按需加载。一次账号请求最多选择一个行业 Skill。

Skill 可以提供有界候选路径、可选的版本化默认内容根、条件式局部分支边界和不可假设项，但不能决定账号定位、受众、人设、表现形式或变现，也不能把正文拼进用户原话。没有 `default_root` 时仍由通用裁决比较；存在 `default_root` 时，通用裁决保留为审查意见，但不能在同一轮静默覆盖该行业 Skill 的版本化默认。

局部分支边界不是一条只约束选根的提示。当前业务表达没有显式激活的分支必须贯穿内容地图、`IncubationBrief`、账号路线模型输入和持久化前校验；用户原话明确提到该场景时，调用方不传入该分支边界。

## 原因

把每次行业纠错写回总提示词，会让黄金礼品、婚礼、水果、海鲜、火锅、旅行等互相污染，并形成无法回归的补丁链。完全依赖通用模型又会在行业内部的高频搭配上停留，例如把黄金礼品收缩为婚礼馈赠。按需 Skill 能隔离行业经验、独立评测和版本化，同时保留模型对新行业的开放泛化。

## 约束

- 不按单品或单个案例创建 Skill；只有可复用于一类业务的经验才允许拆出。
- 用户原话、行业 Profile、对标证据和外部事实必须保持独立来源。
- Profile 必须有大小、Schema、包路径和启用状态校验。
- 局部分支边界在用户明确经营该场景时失效，避免把婚礼业务本身错误排除。
- 行业默认根只属于当前明确选择的 Skill 版本；不得把它提升为总提示词规则或跨行业默认。
- 经营身份不能被改写为既有经验、案例、素材或能力；先断言后补“未确认”仍视为事实越界。
- 没有命中 Skill 的行业继续走原有通用路径，直到独立评测证明新 Skill 值得加入。
- 未经真实模型端到端验收，不得把某个行业 Skill 标记为生产可用。

## 首个实现

`incubate-gift-human-relations` 为首个已验收 Skill。它把礼品行业的人情关系路径设为版本化默认根，并将未被用户业务表达激活的婚嫁相关场景排除在地图和路线之外。A116 记录了候选根被通用裁决覆盖、后段重新引入局部分支、经营身份冒充经验三次真实失败及对应修复。
