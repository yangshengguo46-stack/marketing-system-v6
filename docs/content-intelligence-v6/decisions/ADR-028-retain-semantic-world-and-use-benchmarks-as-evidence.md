# ADR-028：保留语义与内容世界，对标账号只作为机制证据

## 状态

Accepted，2026-08-19。适用范围仅为当前第六版孵化架构边界，不代表内容根实现已经达到最终质量。

## 决定

不采用“单靠对标账号拆解替代语义理解、内容根和内容地图”的架构。正式账号路线必须同时读取用户事实、
已选择的候选内容世界和正式对标证据；对标证据可以支持、反驳或限制路线，但不能自行生成用户能力、裁决
内容根或把成熟账号现状改写成冷启动策略。

继续采用 A98 的最小连接件方向：将稳定账号、多作品、MediaKit 时序观察和受众互动压缩为
`AccountPatternEvidence`，接入现有 `develop_account_strategy` 的证据输入。它保持只读，不写项目定位。

## 理由

- A101 的真实账号证据成功提取了表现机制、受众接续和不可复制条件，证明该模块有直接价值。
- 纯对标组擅自把腕表从业者写成非专家摸索者，证明账号证据不能补齐用户身份。
- 薄内容世界组编造客户、维修能力、表款与事件，证明完整感和模型裁判高分不等于事实正确。
- 两组都围绕样本账号已有的实物、工作台和个人故事收敛，没有打开腕表的人物、历史、地域、事件和作品世界。
- 单个成熟账号只能证明“有人这样讲过、受众这样回应过”，不能证明“新用户应该长期只讲这些”。

## 后果

- 保留 `用户事实 -> 语义/候选内容世界 -> 对标机制证据 -> 条件化路线 -> 用户确认` 的责任顺序。
- 用户未提供身份、技能、资源、库存、客户案例或拍摄条件时，路线只能列为条件和未知，不能自动补造。
- 路线中的具体选题必须区分用户事实、外部观察、创意假设和待调查事实，并声明所需素材；纯字符串选题合同
  不得进入生产接线。
- 对标采集和普通咨询/选题取证继续分账；对标作品必须绑定稳定作者和作品身份。
- 内容地图负责开放世界方向，对标模块负责真实平台机制和反例，两者不得互相冒充。
- A101 实验代码和回执保持离线，不接入现役 Agent；生产连接件仍需单独测试与真实验收。
- 未来若要重新挑战这一决定，必须使用多行业、每行业多个稳定账号及用户事实完整的全新冻结案例，不能重用
  本轮腕表样本调参。
