# ADR-038 受众前置与营销主体事实合同

## 决定

账号孵化请求必须先解析一个明确的 `MarketingSubjectSnapshot`，再形成冷启动
`AccountAudienceDecision`。只有受众路线已自动解析或经用户选择后，才允许账号起号链继续内容根、
内容地图、对标搜索和账号策略。

这是一条业务依赖，不是所有聊天请求都要走的固定工作流。用户只问单个事实或明确选题时仍可调用对应
能力；只有起号、定位和长期账号策略请求进入该顺序。

## 主体解析

- `user_business` 的事实来源是用户原话和已归属当前项目的可信事实。
- `agent_self` 的事实来源只能是服务端版本化 `HostProductProfile`。第二人称指向当前 Agent 时，不把
  代词原文交给业务语义模块猜测。
- 工具调用必须显式提交 `subject_ref`。Lead 负责按当前话语指代选择值；运行时负责校验它不能与已有
  受众工件的主体类型冲突。
- 产品档案分别列出能做什么、不能做什么、解决什么问题和已有何种证据。显示名称可改，事实必须通过
  新版本变更，不能由模型在回答中自我扩权。

## 受众解析

- 冷启动受众不是一组虚构的人口统计标签，而是业务角色与内容关系假设。
- 必须区分付款/签约者、决策者、使用/受益者、业务真正需要影响的人以及愿意长期观看内容的人。
- 用户事实只支持一条交易关系时直接 `resolved`；差异会改变内容与成交关系时生成二至三条
  `proposed` 路线并停止，用户选择后追加 `confirmed` 后继工件。
- 用户确认精确 option 后，下游以确定性投影固定业务角色、目标人群、需求、行动、市场范围和内容受众；
  模型不得重新选择另一种交易关系。
- 确认调用幂等：重复提交同一 option 复用当前工件，提交不同 option 才作为已解决路线冲突失败。
- 真实平台受众观察属于独立证据层，可以触发未来新版本，但不能倒改旧冷启动判断。

## 未授权事项

- 不要求用户先绑定或登录平台账号。
- 不凭行业、语言或单一产品名猜年龄、收入、地区、性别、家庭状态或购买力。
- 不把受众路线选择塞进内容根或行业 Skill，也不让行业 Skill 覆盖选择结果。
- 不让内容地图同时拥有目标人群、定位、人设、形式或变现判断权。
- 不把 `HostProductProfile` 变成营销文案；它只提供有来源的产品事实边界。
- 不因 Agent 自营销而宣称未验收的平台、制作、发布或增长能力。

## 采用依据

A126 的水果真实链在地图前返回批发、零售和线上直销三条路线；Agent 自营销真实链正确绑定服务端产品
档案，并在用户选择经营决策者后继续内容根、对标和策略。失败工件回放还证明，完整产品事实必须保留在
台账、模型投影必须有界，两者不能混为一份长提示。

因此该合同已接受。运行成本、英文词素噪声、市场范围事实边界和受众假设校准仍是后续质量工作，不撤销
主体与受众顺序。
