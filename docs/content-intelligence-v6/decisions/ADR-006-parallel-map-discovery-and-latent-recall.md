# ADR-006：地图方向发现与模型联想并行

- 日期：2026-08-15
- 状态：accepted（受限范围）

## 问题

ADR-005 的真实黄金礼品回归已经正确选择“中国人情往来与送礼关系世界”，但根后的命名召回虚构了一个事件。旧实现只为模型先想出的名字生成搜索任务，搜索只能证明或否定这个猜测，不能从已经合格的地图中独立发现另一个真实人物、事件或作品。一个坏猜测因此会锁死整条证据链。

## 决策

内容根仍必须先冻结，联网结果不得参与选根。冻结地图完成后分成两路：

1. 模型命名联想读取内容根和地图，提出待核验的具体专名。
2. 地图方向发现不等待专名，直接用内容根和每条实际地图方向搜索公开材料。

第一条地图搜索与模型命名联想并行启动。模型返回后，两路查询按地图、联想交替调度并共享并发与总量上限。搜索回执去重后保留每个来源与研究路线的多对多关联，再由一次证据阅读选择证据最强的路线。

`map_direction_search` 路线允许证据阅读从来源中识别一个新实体；`latent_recall` 路线必须保持原联想实体，禁止把错误猜测换名后继续使用。所选实体必须引用一条观察，该观察必须引用所选路线拥有的来源。阅读可以比较所有路线，但确定性投影会在创意收敛前删除未选路线的观察和来源；旁路噪声不能让整份有效阅读作废，也不能给获胜路线借证据。

搜索摘要只用来发现，不视为已阅读原文。去重后的公开 URL 优先由本地受控读取器打开，失败时再使用运营者配置的 `web_fetch`。本地读取器重新校验每一次跳转、拒绝非公网地址与非文本响应，并限制页面体积与进入模型的字符数。

该改动不增加自由行动子 Agent，不修改语义阅读、内容根选择或冻结地图，也不把搜索提前到选根之前。查询数量和并发数只是成本边界，不是内容配额。

## 失败测试与证据

新留出的“共享用餐”测试先在旧实现上得到两处红灯：地图方向搜索没有启动；`EvidenceReadingDraft` 不允许记录搜索发现的实体。实现后验证：

- 地图搜索与联想候选搜索可同时处于执行状态。
- 一个不可靠的联想候选存在时，地图方向发现的公开事件可以胜出。
- 模型没有召回任何名字时，地图方向路线仍能独立形成 `TopicBrief`。
- 联想路线不能更换实体，所选实体必须绑定观察。
- 两路轮转不能破坏来源隔离、弱证据弃权、冻结根和可选叙事边界。
- 单一结构化合同收到多个工具调用时确定性失败，不再静默采用第一份。
- 未选路线的已知噪声会被投影掉，未知来源和跨路线借证据仍然拒绝。
- 原文打开成功时替换搜索摘要；本地与配置读取器都失败时保留搜索回执并允许弃权。

真实黄金礼品回归最终以地图搜索路线胜出，8 个唯一搜索结果中打开 6 篇正文，形成一条有来源、反面解释和继续核验项的具体选题。该结果批准双路发现、原文阅读和获胜路线投影进入第六版候选架构，不等于跨行业验收。

## 后续边界

- 不在查询模板或提示词中写入黄金礼品、人情往来等行业答案。
- 不让网页搜索选择或修改内容根。
- 不把搜索摘要冒充全文或原始档案。
- 本次内容根从广义人情往来收窄到婚嫁赠受，且具体选题包含一条已明示为二手转述的历史结论；这两项保留为语义稳定性与事实边界风险。
- 不因一次真实案例通过就宣称跨行业稳定；仍需海鲜、腕表、医美、雪茄馆等新会话回归。
