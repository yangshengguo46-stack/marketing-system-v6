# ADR-019: 有界并行语义工作者与单一内容根裁决

## 状态

`adopted as working checkpoint; downstream topic work unblocked`

## 背景

内容孵化内核需要同时完成商业表达阅读和词义世界探索。它们共享同一个用户输入，但在首轮没有
相互依赖；内容根裁决依赖两路候选，内容地图又依赖已经冻结的根。原实现将六次模型调用全部串行，
延迟高，同时让每个后继工作者重复解释前序结果。

DeerFlow 已有 `task` 子 Agent 适合可独立失败的研究任务，但这两个首轮工作者需要严格结构化合同、
确定性合流和同一次工具运行内的错误边界。把它们升级为自由子 Agent 会增加上下文、工具和状态开销，
也会弱化类型约束。

## 决策

1. 在 `explore_content_world` 内并行启动两个只读结构化工作者：业务语义阅读和词义世界阅读。
2. 两者只共享原始 `subject_expression`，互相不可见，不拥有工具、项目状态或最终判断权。
3. 由确定性代码完成词法范围、意义成分、可选词义证据和构成语境合流。
4. 合流后只运行一个内容根裁决器；地图只在根冻结后运行一次。
5. 不使用投票、平均或多数表决来选根，也不为提速并行存在数据依赖的阶段。
6. 单个可选工作者失败时保留其他候选并显示未知；核心业务语义失败时取消并回收同轮任务。

## 理由

- 两个首轮任务真正独立，并行能减少墙钟时间。
- 结构化合同和确定性合流让冲突可检查，而不是让 Lead 猜哪位子 Agent 正确。
- 单一裁决器保留营销判断的一致性，避免重现第四版多处争夺决策权的问题。
- 继续使用现有 DeerFlow Tool 和模型工厂，不引入第二套 Agent 运行时。

## 不采用

- 不把每个语义步骤都变成 DeerFlow `task` 子 Agent。
- 不让地图在内容根尚未冻结时提前猜测多个世界。
- 不用固定行业词表或黄金礼品标准答案修补失败案例。
- 不以增加并发调用数量替代提示合同、语境绑定和真实业务验收。

## 验收

- 自动测试必须证明两路首轮调用真实重叠，而不是仅检查存在 `create_task`。
- 任一分支不能通过共享可变 Schema 污染另一分支。
- 构成语境丢失的候选不能进入地图。
- 至少一个此前失败的非黄金案例真实通过，并记录每阶段耗时。
- 黄金礼品仍未到达人情世故时必须诚实保留失败记录，但按用户决定不再阻塞具体选题模块。
