# ADR-014：只在词义选定后比较稠密向量召回

## 状态

`rejected / frozen experiment complete`，2026-08-16。

## 问题

A30 采用了结构化 CC-CEDICT 证据，但没有运行用户要求的真实向量库实验。直接对原商业
表达或尚未消歧的词条做向量查询会放大最近品类：例如“礼”同时具有 gift、rite、etiquette
等义项，把全部释义拼成查询时，近邻很容易继续集中于礼物、礼盒和赠品。这不是缺少召回，
而是在义项尚未确定时过早召回。

## 冻结候选

1. 数据仍为同一份 CC-CEDICT 2026-08-15 索引，不引入无授权《现代汉语词典》。
2. 使用 `BAAI/bge-small-zh-v1.5` 的 Qdrant ONNX 转换、FastEmbed 0.8.0 和 sqlite-vec
   0.1.9；冻结 Hugging Face 快照与本地模型工件 SHA-256。
3. 结构化精确义项与词族先运行。只有隔离词义工作者已经输出真子成分及
   `selected_meaning` 后，向量才以这两个字段为查询锚点。
4. 向量近邻以独立 `semantic_recall` 证据进入共同世界阅读，不回流到词法消歧，不修改
   已选义项，不直接进入根分数，也不增加一次模型调用。
5. 召回每个锚点最多 6 条，模型投影最多 3 KB；本地路径不进入模型、日志或评测结果。
6. 构建器绑定词典内容哈希、模型 ID、模型快照、模型工件哈希、运行时版本、维度和词条数；
   维度漂移原子失败，不保留半成品。
7. 冻结运行时，实验代码仅位于 `backend/experiments/lexical_vector`，没有接入默认工具工厂、
   Lead、MCP、Skill 或用户运行时。

## 决策门槛

四臂比较为纯模型、精确义项、精确义项加结构化关系、结构化关系加词义后向量召回。全部
使用 GLM-5.2、关闭思考、相同合同与最大上下文预算。第四臂必须提高或持平最终内容根与地图
人工结果，同时不得增加机械拆词、商品邻近、抽象空话或事实冒充。延迟与 Token 单列，不用
召回分数替代业务验收。

冻结的七个案例、合法替代答案和逐次回执见 `evidence/dense-vector-a32-2026-08-16.md`。本 ADR 在
唯一冻结运行完成后改为 adopted、rejected 或 deferred，不根据单个漂亮案例边跑边调。

## 唯一冻结运行

七案例乘四臂共 28 次，27 次合同成功。稠密向量实际产生候选的只有两个案例：

- `家谱修复`从家谱、世系和代际记忆退化为泛化的“把东西恢复原状”。
- `婚书定制`从婚姻关系与书面凭据退化为“婚书”，并召回了带贬义的无关词“婚驴”。

因此在可归因的两个样本中，向量为 `0/2` 改善、`2/2` 恶化。其他五个向量臂
没有产生任何向量候选，与关系臂的回答差异只能视为模型采样波动，不得计为向量收益。
向量臂平均 131.25 秒、输入 76,076 Token、输出 34,095 Token，均高于结构化关系臂的
121.98 秒、73,669 与 32,400。

## 决策

拒绝将该稠密向量候选接入默认运行时、Lead、MCP、Skill 或本地 canary。正式分析器删除
`semantic_recall_provider`、模型可见的 `semantic_recall` 提示和相关运行合同。用户确认舍弃后，
实验代码、构建脚本、专用测试、本地向量索引、模型缓存和原始评测文件一并删除；只保留本 ADR 与有界结果回执作为失败经验。现有结构化精确义项与关系证据保留，但本轮不宣称它们已成为最优语义架构。
