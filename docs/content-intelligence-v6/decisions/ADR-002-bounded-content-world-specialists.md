# ADR-002：用受控多专家拆开内容世界判断

- 日期：2026-08-15
- 状态：superseded in root-selection criterion by ADR-005

## 决策

宽泛起号和长期内容请求不再使用一次大而全的结构化调用，而是由 `explore_content_world` 串行组织四个受控专家：

1. 语义阅读专家拆商业对象、词法主词、修饰关系、用途与活动。
2. 内容根专家在对象、活动、功能和关系世界之间选择内容中心；当时采用的“最小完整中心”标准已由 ADR-005 覆盖。
3. 地图专家只接收冻结的 `content_root`，不接收商品和用户原话。
4. 总编专家只读语义跃迁、冻结根和地图，直接返回 Markdown 正文。

总编结果先进入带直达标记的隐藏 `ToolMessage`，由 DeerFlow 原生
`return_direct` 结束模型循环，再由终局中间件提升成唯一可见的
`AIMessage`。通用 Lead 不得再次综合或改写。`ContentWorldView` 不再包含商业锚点或回桥。

## 原因

黄金礼品连续失败表明，当一个调用同时看到商品、内容地图、起号交付和商业承接时，模型会把注意力拉回产品目录与通用运营模板。单纯加强 Lead 提示词无法稳定阻止这个改写。最小化每个专家的可见上下文，是当前最直接的注意力隔离。

第五版 Git 谱系还显示，账号尺度的商业归因先被提前写进选根器，随后成为 `return_path` 必填评测字段，并被第六版初始合同继承。问题不是商业承接目标错误，而是下游目标反向控制了上游理解。为避免否定提示继续激活同一概念，运行时合同只正面描述各专家负责输出什么；“商业回桥”一词仅保留在审计与本 ADR 中。

## 不采用

- 不把四个角色改成可以自由使用工具和写状态的 `task` 子 Agent。
- 不在地图专家输入中加回商品、候选根、用户起号问法或销售目标。
- 不要求长文总编把中文正文序列化成 JSON。
- 不使用产品回桥、发布节奏、数量或转化计划补齐地图。

## 验收与剩余风险

冻结的黄金礼品案例已在真实 GLM 运行中从商品跃迁到礼品馈赠活动与人际关系世界；重庆火锅底料案例也已稳定选择“火锅”并完成单答案页面验收。仍需要海鲜、水果和全新留出题验证跨品类稳定性。GLM 深度思考的延迟与 Token 成本仍未解决，不能因两个案例通过就宣称营销脑达到 80 分。
