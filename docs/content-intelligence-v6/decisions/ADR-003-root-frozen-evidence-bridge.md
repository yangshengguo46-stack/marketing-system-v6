# ADR-003：根冻结后再研究，弱证据允许弃权

- 日期：2026-08-15
- 状态：accepted after live evaluation

## 决策

`explore_content_world` 保持一条受控串行链：

```text
用户原话
-> 语义阅读
-> 内容根选择
-> 冻结根地图
   -> 内容世界总编 -> 地图正文
   -> 命名召回 -> 有界网页搜索 -> 证据阅读 -> 选题总编 -> 可选 TopicBrief
-> 确定性合并地图正文与可选证据选题
-> return_direct 单次交付
```

Lead 不能在同一轮并行发起通用起号搜索，也不能向该工具注入模型改写的来源。命名召回只看冻结根和地图；搜索与阅读不得修改内容根。没有自然命名候选、搜索失败、合同失败或证据只有推广与无出处页面时，保留原地图并允许 `TopicBrief` 为空。

外层 Lead 可以按用户选择使用供应商思考模式。工具内受控工作者固定关闭供应商隐藏思考，以结构化中间记录暴露判断并兼容不支持“思考 + 结构工具选择”的模型。

## 原因

KTV 实测证明，先搜索“怎么起号”会把注意力拉向平台模板、设备与经营；即使内部地图已经召回唱歌与文化，最终 Lead 仍会被并行搜索覆盖。搜索必须依赖已经冻结的内容根，而不能参与选根。

陶艺实测又证明，活动根容易被改写成组织者的定价、获客与排班。冻结地图因此按参与者的动作、技能、感受、关系、成果、失败、历史与文化展开；除非根本身明确是经营主题，否则卖方运营不进入地图。

## 不采用

- 不让通用 Lead 自行决定先搜索什么行业起号资料。
- 不把搜索结果、商业对象或用户原问法重新喂给地图专家。
- 不用固定人物数、查询数或必须生成选题的业务配额。
- 不用弱来源填满“已取证”段落；证据不足时不生成 TopicBrief。
- 不为每个受控工作者开启供应商隐藏思考。
- 不引入向量数据库、GraphRAG 或第二 Agent 运行时。

## 验收

KTV 真实运行选择唱歌/K歌体验并保留社交与情绪宣泄；婚礼主持留出题选择婚礼仪式，搜索证据不足时正确省略 TopicBrief。陶艺复跑清除了组织者运营地图，但内容根命名仍略宽，作为剩余风险保留。详细线程、成本和失败谱系见 `../LEDGER.md` 的 A12-A13。
