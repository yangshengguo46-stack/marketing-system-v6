### Agent System

**Lead Agent** (`packages/harness/deerflow/agents/lead_agent/agent.py`):
- Entry point: `make_lead_agent(config: RunnableConfig)` registered in `langgraph.json`
- Dynamic model selection via `create_chat_model()` with thinking/vision support
- Tools loaded via `get_available_tools()` - combines sandbox, built-in, MCP, community, and subagent tools
- System prompt generated by `apply_prompt_template()` with skills, memory, and subagent instructions

**Model-neutral product identity** (`packages/harness/deerflow/agents/lead_agent/IDENTITY.md`,
`identity.py`, and `agent_core_contract.py`):
- Every provider receives the same minimal Agent kernel; provider adapters only own protocol, thinking, context,
  streaming, and error normalization.
- `IDENTITY.md` is the packaged, read-only default product identity. `identity.py` validates its single
  `<agent_kernel>` block and `{agent_name}` placeholder, enforces the 1,600-byte budget, and exposes a content-addressed
  version. `agent_core_contract.py` imports that asset; it must not maintain a second copy of the identity text.
- The kernel defines five things only: the Lead is an employee inside the user's team, its enduring attention/IP
  mission, autonomous judgment and action, the distinction between facts and bold judgments, and explicit approval
  before irreversible external actions. It does not prescribe an incubation route, search order, question count,
  output template, platform rule, score, or model-specific behavior.
- Keep `PRODUCTION_AGENT_KERNEL` at or below 1,600 UTF-8 bytes and `SYSTEM_PROMPT_TEMPLATE` at or below 5,000 bytes.
  Industry methods live in Skills, tool protocols in schemas, and account truth in business artifacts.
- Deferred Skill discovery exposes a name plus at most 120 characters of routing summary. Full metadata still requires
  `describe_skill`; method bodies still require `read_file`. A real name-only trial reduced greeting cost but failed the
  golden-gift route and returned to marriage/product topics, so do not remove the bounded summary merely to save prompt
  tokens. See A142/ADR-048.
- A138's strong completion candidate and A139's stacked business contracts are superseded for production. Do not add
  provider-specific marketing prompts, output-rewrite middleware, a fixed review-agent pipeline, or another mandatory
  workflow to hide residual consultant-style behavior.
- User-created Agent identity or SOUL assets are separately scoped configuration. Ordinary chat and `setup_agent`
  cannot rewrite, shadow, or fall back to the packaged default product identity.

**Sourced user profile** (`user_profile.py`, `middlewares/user_profile_middleware.py`, and
`tools/builtins/user_profile_tool.py`):
- The profile contains at most 16 stable cross-project user facts or collaboration preferences. Project/account,
  brand/product/audience, temporary-task, model-inferred, and permission-granting data do not belong in it.
- `manage_user_profile` is a Lead-only reversible tool. Every remember/replace/forget request must quote an exact
  excerpt from the latest visible user message; each immutable user-scoped revision stores source hashes and a
  previous-content hash. Native subagents must set `include_user_profile_tool=False`.
- `UserProfileMiddleware` injects at most 2,400 UTF-8 bytes as hidden per-call context after dynamic context. The current
  user message remains later and authoritative. The projection cannot grant tool or external-action permission.
- ContextManifest reads only owner-token-authenticated version/hash/count metadata from protected runtime context.
  Profile text, local paths, and owner tokens must not enter RunEvents, logs, frontend payloads, or model metadata.
- The legacy repository-root `USER.md` is not a default Lead source. Automatic extraction, vector retrieval, and
  cross-user learning are not part of the first version.

**Shadow context manifest** (`packages/harness/deerflow/agents/middlewares/context_manifest_middleware.py`):
- The Lead stack appends this middleware after all model-request transformers and before extension composition. It
  observes one physical provider call without mutating the request or controlling model behavior.
- It writes one `context:manifest` RunEvent per call with identity/version presence, model and settings-key identity,
  message/hidden-layer byte accounting, visible tool names and schema hashes, response-format accounting, summary and
  delegation counts, inspected versus activated Skill state, authenticated UserProfile version/counts, and
  provider-reported token usage when available.
- It must never persist message content, tool descriptions or arguments, Skill paths, credentials, runtime secret
  values, or provider error text. Byte counts are estimates before provider-specific serialization; only returned usage
  metadata is token evidence.
- `MODEL_PHYSICAL` extension observers are anchored immediately inside the manifest. They remain read-only observers of
  the same final request; conditionally disabling safety middleware does not alter that primary anchor.

**ThreadState** (`packages/harness/deerflow/agents/thread_state.py`):
- Extends `AgentState` with: `sandbox`, `thread_data`, `title`, `artifacts`, `todos`, `uploaded_files`, `viewed_images`, `goal`, `promoted`, `delegations`, `skill_context`, `summary_text`
- Uses custom reducers: `merge_artifacts` (deduplicate), `merge_viewed_images` (merge/clear), `merge_goal` (preserve the active goal across ordinary state updates unless the goal writer replaces it), `merge_promoted` (catalog-hash-scoped deferred tool promotions), `merge_delegations` (append task delegation entries, same id latest wins, terminal status never downgraded, capped to the most recent entries), and legacy `merge_skill_context` (dedupe inspected-Skill references by path; references are non-authoritative and never activate tools or secrets). Actual Skill activation is run-scoped in protected runtime context via `/skill` or `activate_skill`. `summary_text` is a LastValue channel updated by summarization and projected into model requests as durable context data instead of being stored as a `messages` item.
- Delta-mode `merge_message_writes` normalizes the current message state once,
  then folds normalized writes in order with message-ID position indexes and
  deferred tombstone compaction. It preserves public `add_messages` behavior,
  including duplicate IDs, replacement position, removal errors,
  `REMOVE_ALL_MESSAGES`, null-write errors, and missing-ID allocation order,
  without rescanning the accumulated state for every write. Keep this
  full-parity contract covered by differential tests: LangGraph's private
  `_messages_delta_reducer` is also linear, but intentionally omits some of
  those public `add_messages` semantics and cannot be substituted directly.

**Runtime Configuration** (via `config.configurable`):
- `thinking_enabled` - Enable model's extended thinking
- `model_name` - Select specific LLM model
- `is_plan_mode` - Enable TodoList middleware
- `subagent_enabled` - Enable task delegation tool
- `max_concurrent_subagents` - Per-response `task` call concurrency limit (clamped by `SubagentLimitMiddleware`)
- `max_total_subagents` - Optional per-run total delegation cap override (falls back to `subagents.max_total_per_run`, clamped to 1-50)
  Gateway and `DeerFlowClient.stream()` always provide the runtime `run_id`; custom
  graph integrations must do the same. If it is absent, enforcement deliberately
  counts the thread's full delegation ledger (fail-restrictive) and emits a warning.
