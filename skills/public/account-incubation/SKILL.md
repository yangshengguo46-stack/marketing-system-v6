# 通用起号判断

## 你在解决什么

当用户说“我是做 X 的，怎么起号”“这个业务怎么做账号”或同义请求时，默认任务是：

> 为用户建立一个公开内容账号，让正确的人注意、理解、记住并持续回来，而不是给一份行业经营或后台操作教程。

“X 是什么”只是业务输入，不是回答的标题。资质办理、团队管理、供应链、主播培训、投流或后台配置，只有用户明确询问时才是当前任务。不要因为熟悉这些知识，就把起号问题改写成经营 SOP。

## 形成当前判断

先弄清这门业务希望谁发生什么变化，并区分：

- **业务目标**：最终希望谁咨询、合作、购买、加入或传播。
- **内容受众**：谁会因为内容本身停留、看完、关注并回来。

两者可以重合，也可以不同。信息不完整时，给出标明假设的工作判断并继续；只有缺失的用户事实会真实改变方向、且无法形成有用初稿时才提一个问题。

寻找一个可长期成立的账号方向：这个账号替哪类人观察什么世界，以什么独特视角持续提供什么价值。若存在几条实质不同的路线，比较少量候选并明确推荐；候选应在受众、承诺、内容世界或叙述视角上真正不同，不能只是把同一内容换成口播、短剧或图文。

用户问的是起号时，当前答案通常应落到一个能直接进入拍摄或成稿的选题。它应有具体主体、事件或问题，说明观众为什么会在意，并给出与用户立场相连的明确观点或观察角度；“分享行业知识”“建立信任”“记录日常”不算具体选题。除非用户继续要求，不必为了显得完整而附加脚本、日历或长期执行表。

## 何时找证据

事实和现状会改变判断时主动查证，而不是用模型印象补齐：

- 新近、陌生或有歧义的业务词，只做一次有界释义核验。
- 平台型、区域型、快速变化或高度依赖既有内容生态的业务，真实对标往往会改变起号方向。此时可用 `tool_search` 发现当前可用的搜索或对标能力，优先查看可验证的公开账号、作品和受众反应，再看泛行业文章。
- 对标用于理解观众已经被什么内容教育、哪些表达已经拥挤、哪些位置仍可占领；它不替用户决定定位，也不能把成熟账号的结果冒充冷启动方案。

`tool_search` 是能力目录，不是搜索引擎。已知候选工具名时，优先精确发现，例如
`select:web_search,web_fetch,collect_douyin_benchmark_account,collect_douyin_benchmark_candidate`；不要把“search web competitor account”之类自然语言当成网页查询交给能力目录。精确选择只让工具变得可用，不代表本轮必须全部调用。

研究只服务于当前账号方向，不负责写完一份行业报告。从一个最能改变判断的查询开始；结果已经足够区分受众、内容空位和方向时就停止，不要并行发起多个近义查询来追求表面完整。

证据量由判断需要决定，没有固定样本数。找不到可靠对标时，说明证据缺口，仍可交付一版可纠正的初步判断。把观察、推断和创意分开，不把搜索摘要、播放量或单个案例写成普遍规律。

搜索结果页只用于发现候选来源。涉及法律、政策、数字、平台规则或具体账号表现时，应读取可归属的原文，并优先采用官方或第一方资料。一次正文读取失败后，不要换网址连续重试同一事实；删除这条细节并继续交付，或明确写成待核实并换一个不依赖它的选题。不要把摘要里的说法升级成已核实事实或正式引用。

产品或服务是否具备某项能力、能否实施某个场景、是否符合安全或平台要求，都是需要来源或用户事实支持的外部事实，不能从业务名称直接推断。无法查证时，把它写成待确认的前提，并换用不依赖该前提也成立的方向或选题；不要为了让方案显得具体而设计用户未必做得到的拍摄动作。

## 保持 Agent 自主

这不是一个流水线。没有固定步骤、固定提问数、固定样本数或固定输出模板。语义解释、内容地图、对标采集、账号方向提案和持久化状态都只是可选能力；只有它们会实质改善当前答案时才使用。

发送前只做一次事实清理：删除或改写用户未提供的第一人称经历、案例、素材、能力、渠道或权威，例如“我服务过的一个客户”“我每天都在处理”；删除无法读取原文支撑的比例、预算、时间、数量、政策和平台规则。不要自动给出固定周期的养号计划。事实不足可以保留未知，但判断不能因此退化为让用户自己完成的问卷或泛泛建议。
